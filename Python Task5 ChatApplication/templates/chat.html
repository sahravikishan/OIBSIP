Security & Privacy Transparency

Important Notice: This application communicates real-time messages and records history to an SQLite database. It is transparently designed without false security claims.

1. Password Protection

Passwords are never stored in plain text. They are hashed using PBKDF2-HMAC-SHA256 with a unique 16-byte random salt per user (via Werkzeug security). The plain-text password cannot be extracted from the database.

2. Message Storage & Server Access

All chat messages are stored persistently in a local SQLite database (database/chat.db) with message text, author ID, room ID, and UTC timestamp. Because messages are stored in plain text on the server, anyone with administrative access to the server host or SQLite file can inspect messages.

3. End-to-End Encryption Limitation

This application is NOT end-to-end encrypted (E2EE). While real-time WebSocket communication operates between browser and server, the server terminates the connection and possesses the full content of all communications.

4. Transport Layer Security

In local development, traffic runs over cleartext HTTP and WS. In a production deployment, traffic must be routed through HTTPS and WSS (TLS/SSL) to protect against eavesdropping on public networks.

5. Injection and XSS Defenses

All database queries strictly employ parameterized SQL (? placeholders) to prevent SQL injection. Chat message rendering in the browser uses DOM text node insertion (preventing Cross-Site Scripting / XSS execution).
